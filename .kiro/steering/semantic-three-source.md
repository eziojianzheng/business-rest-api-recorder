# 语义步骤生成：三源融合硬规则

## 核心原则（不可违背）

将录制转换成语义步骤时，**每一个 step 的描述都必须经过三源交叉验证**，缺一不可：

1. **录制脚本**（`ui-script.js`）—— Playwright 选择器，确定"点/填了什么、操作类型"
2. **HAR 网络**（`network.har`）—— 该步触发的后端 API，确定"服务端实际做了什么"（创建返回的 ID、提交是否 200、是否报错）
3. **前后截图**（`steps/*.jpeg`）—— before/after 图片，**必须用视觉打开核对画面变化**

## 分析顺序

对每一步：**先看脚本 → 再看 API → 最后必须打开 before/after 图片视觉确认 → 三者一致再下结论。**

- 若三源冲突，或截图显示的与脚本/API 不符：**以截图所见为准**，并在描述中标注差异。
- 尤其画布拖拽、`div`/`svg`/`path` 等无语义元素的操作：**只有看图才能确定实际效果**，不能仅凭脚本猜测。

## 数据来源

工具在点击"生成语义脚本"时，会自动调用 `semantic-input-builder.js`，
在 `semantic-context.md` 里为每一步生成三源证据清单（脚本证据 + HAR API + 图片路径）。
按该清单逐步分析即可。

## 前提

三源里的"图片"依赖录制时开启 **🎬 录屏(Trace)**（默认开启）。
若某次录制没有 `steps/` 目录，说明未开 Trace，语义分析会缺失视觉一源——
此时应提示用户开启 Trace 重新录制，而不是仅凭脚本+HAR 硬猜。

## 可信度标注（建议在语义输出中保留）

- ✅ 有 API 或 id/name 硬证据 + 图片确认
- 🟡 有元素语义 + 图片确认，但无 API
- ⚠️ 三源有冲突或某源缺失（需说明以哪一源为准）
