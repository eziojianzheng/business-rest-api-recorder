# Skill 评估助手

当用户提到"添加新 Skill"、"引入 Skill"或类似需求时,使用此指南帮助评估。

## 快速评估流程

### 第一步: 询问基本信息

```
你想添加什么 Skill? 请告诉我:

1. **Skill 名称**: [例如: api-doc-generator]
2. **主要功能**: [用一句话描述]
3. **使用场景**: [什么时候会用到]
4. **与 UI Recorder 的关系**: [是否协同工作]
```

### 第二步: 评估必要性

根据用户回答,进行评估:

| 评估项 | 问题 | 权重 |
|--------|------|------|
| 协同性 | 是否与 UI Recorder 协同? | ⭐⭐⭐ |
| 长期性 | 是否会长期使用? | ⭐⭐⭐ |
| 通用性 | 是否足够通用? | ⭐⭐ |
| 独立性 | 是否不引入大量依赖? | ⭐⭐ |
| 唯一性 | 是否不与现有功能冲突? | ⭐ |

**评分标准**:
- ⭐⭐⭐ 项: 必须满足
- ⭐⭐ 项: 建议满足
- ⭐ 项: 可选满足

### 第三步: 给出建议

根据评估结果:

#### ✅ 推荐添加 (满足 3+ 个 ⭐⭐⭐ 项)
```
✅ 推荐添加这个 Skill!

建议的目录结构:
skills/[skill-name]/
└── SKILL.md

我可以帮你:
1. 创建 Skill 目录
2. 生成 SKILL.md 模板
3. 更新项目文档

需要我现在开始吗?
```

#### ⚠️ 谨慎添加 (满足 2 个 ⭐⭐⭐ 项)
```
⚠️ 这个 Skill 可以添加,但建议考虑以下问题:

[列出未满足的评估项]

替代方案:
1. [方案 1]
2. [方案 2]

你想继续添加,还是考虑替代方案?
```

#### ❌ 不建议添加 (满足 < 2 个 ⭐⭐⭐ 项)
```
❌ 不建议添加这个 Skill,原因:

[列出主要问题]

推荐的替代方案:
1. 使用 .kiro/steering/ 存放临时指南
2. 在对话中直接提供指令
3. 作为独立项目维护

需要我帮你实现替代方案吗?
```

## 特殊场景处理

### 场景 1: 用户想添加大型平台类 Skill
**识别**: 包含多个子模块、大量配置、复杂依赖

**回应**:
```
我注意到这是一个比较大型的 Skill,类似之前的 CETA。

为了保持项目清晰,我建议:

方案 A: 拆分为多个小 Skill
- [列出可能的拆分方式]

方案 B: 作为独立项目维护
- 在单独的目录或仓库中管理
- 通过 MCP 或其他方式集成

方案 C: 使用 steering 文件
- 将指南放在 .kiro/steering/ 目录
- 不作为正式 Skill

你倾向于哪个方案?
```

### 场景 2: 用户想添加临时性 Skill
**识别**: 只用一次、特定项目、短期需求

**回应**:
```
这看起来是一个临时性的需求。

建议使用 steering 文件而不是 Skill:

1. 创建 .kiro/steering/[任务名].md
2. 写入指导内容
3. 任务完成后可以删除

这样更灵活,不会影响项目结构。

需要我帮你创建 steering 文件吗?
```

### 场景 3: 用户想添加与现有功能重复的 Skill
**识别**: 功能与 ui-recorder 或其他 Skill 重叠

**回应**:
```
我注意到这个功能与现有的 [Skill 名称] 有重叠。

建议:

方案 A: 扩展现有 Skill
- 在 skills/[现有 Skill]/SKILL.md 中添加新功能
- 保持功能集中

方案 B: 合并相关功能
- 创建一个更通用的 Skill
- 替换现有的 Skill

你想选择哪个方案?
```

## 创建 Skill 的标准流程

当确认添加 Skill 后,按以下步骤执行:

### 1. 创建目录结构
```bash
mkdir skills/[skill-name]
```

### 2. 生成 SKILL.md
使用模板创建,包含:
- name
- description
- triggers
- 功能说明
- 使用方法
- 示例

### 3. 测试 Skill
- 发送触发词测试
- 验证功能正常
- 检查无冲突

### 4. 更新文档
- 更新 README.md
- 添加到 Skill 列表
- 说明用途

### 5. 确认完成
```
✅ Skill 添加完成!

已创建:
- skills/[skill-name]/SKILL.md
- 已更新 README.md

测试方法:
在对话中发送 "[触发词]" 即可激活。

需要我帮你测试吗?
```

## 维护现有架构的检查点

在添加 Skill 的每个步骤,检查:

- [ ] 是否只在 skills/ 目录下操作
- [ ] 是否没有修改现有文件
- [ ] 是否没有添加项目级依赖
- [ ] 是否保持了目录结构清晰
- [ ] 是否更新了相关文档

## 回滚方案

如果添加后发现问题:

```
如果需要移除这个 Skill:

1. 删除目录:
   Remove-Item -Recurse -Force "skills/[skill-name]"

2. 恢复 README.md:
   [移除添加的 Skill 说明]

3. 验证其他功能正常

项目会恢复到添加前的状态。
```

## 总结

**核心原则**: 
- 保守添加,大胆删除
- 优先扩展,避免重复
- 保持简洁,拒绝臃肿

**记住**: 
每个 Skill 都是项目的一部分,添加前请三思!
